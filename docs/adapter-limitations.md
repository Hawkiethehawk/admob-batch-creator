## 已校准的真实结构

### 身份

应用名称来自当前选中的 `material-list-item` 显式标签或应用标题；忽略“前往所有应用”类导航。发布商前缀从当前应用广告位的 `ca-app-pub-<16 位>/<10 位>` 核对，App ID 优先取设置页显式值，并与当前 `/v2/apps/<数字>/` 路由一致；未打开设置页时可由当前发布商和路由组合。每次执行都重新核对，不用跨应用历史缓存，不把 `~` App ID 当作 `/` 广告位 ID。

### 列表与搜索

列表为 `div.ess-table-canvas[role="grid"][aria-label="广告单元"]`，行使用 `particle-table-row`，名称/ID 和格式位于对应 `ess-cell[essfield]`，并非 HTML table。名称可能是 SPA 可点击节点，不能假定一定有 `<a href>`。

页脚为“第 A - B 行，共 N 行”，分页使用明确的上一页/下一页/末页控件。“转到首页”可能是站点面包屑。列表有虚拟化，搜索后总数可能先于真实行出现；脚本等待筛选值和匹配行稳定，不能把暂未渲染当作不存在。

新批次预检不查同名、不统计同名数量。每行是独立创建请求，提交后立即持久化新 ID；保存后核验按精确 ID 搜索并打开唯一行，不靠名称区分同名单元。列表本身不显示人工底价或币种，不能单独证明配置成功。

### 创建页

格式卡为 `section.ad-format-card`；插页式、开屏与插页式激励严格区分。名称字段实际上限为 80 字符。人工底价选项显示“人工指定底价”，只有选中后才挂载 `manual-ecpm-floor-input`；高级设置展开和人工模式回读必须先完成，再等待全局底价组件。

按用户已确定的逐行金额与整批 USD 直接使用底价，自动填写和读回。每条提交前仍检查名称、人工模式、金额和创建按钮有效状态，明确非 USD 或配置冲突时停止并报告。只设置全局底价，不设置国家/地区底价和中介组 eCPM。

### 创建成功说明页

第 2 条真实提交后，页面显示新 ID `ca-app-pub-3009710883544946/7014189738` 及成功说明，但页头仍为“创建广告单元”，没有保存详情字段。0.4.5 把它保守视为表单，等待 ID 超时。0.4.6 以真实 `.instructions` 成功说明区及其唯一 ID 识别结果，先持久化新 ID，再通过按 ID 的保存后详情核验完成闭环；不从背景列表或整页扫描取 ID，不再次提交。

恢复已有提交意图、尚无 ID 的任务时，适配器只接受与当前任务名称、发布商、应用及格式精确匹配的成功说明，控制器立即保存 ID 和 `verified:false`，随后才导航到保存详情。没有提交意图不采纳说明凭据，失败保留已恢复 ID 和原执行归属。

### 保存后字段与批次底价

保存详情按明确标签关联的 `.panel-description` 或 `aria-describedby` 值读取。0.4.5 不再扫描整页正文或任意父容器回填字段：AdMob 可能在编辑器背后保留旧列表，扫描整页会混入其他广告位的 ID、格式和金额。一个标签出现多个不同值时停止核验。

保存后的 ID、名称、格式、人工模式与金额都须与同一已知 ID 的请求匹配；币种使用已确定的整批 USD，明确非 USD 时报告冲突。ID 不同不会覆盖原已知记录；字段缺失、关联不明确或任一不一致时保留“已创建但配置待核验”，禁止计为成功或重新创建。

保存摘要允许规范三位千分位，如 `$1,000.00`；0.4.14 同样允许真实 `manual-ecpm-floor-input` 内原生 input 在 input/change/blur 后显示 `1,000.00`。准备、最终读回与提交前仍按完整十进制金额精确比较；畸形分组、金额变化、普通 input、textarea 和用户导入不放宽。按已知 ID 搜索最多等待 20 秒，只有精确 ID 行出现才继续；旧无关行和旧零总数不表示过滤完成。

0.4.11 的 `home()` 从创建或详情页返回列表时，使用默认最多 20 秒等待真实列表路由和 grid；列表入口回退也沿用该默认上限。旧 5 秒上限可能在页面仍加载时过早报错。条件满足立即继续，超时仍保留已有 ID 和未核验状态，不将返回列表失败判作未创建。

不再设置 US$ 会话证据门槛，也不为补证额外导航到创建表单。保存字段只显示 `$` 时直接按已确定的批次 USD 解析；面板注明“USD（按批次设置）”，不将此描述为新获取的真实字段证据。整批开始确认、精确 ID 核验及明确配置冲突检查继续保留。

## 暂停恢复与提交保护

0.4.5 为暂停批次开放只读预检，不覆盖清单、已有 ID、意图或分配。待核验项存在时禁用“继续”并解释原因，控制器也拒绝恢复；底价不需要单独确认。核验成功后才设置首条门控通过；已确定的底价政策不替代整批开始确认或防重复提交保护。

交接文档所用 `querySelectorAll('button,input')[22]` 已在五行恢复面板中复现为第 5 行底价输入，不是“继续”。按钮提供稳定 `data-action`；调试不要用固定数组索引，也不要修改 disabled 属性。

0.4.7 修复页面与 Tampermonkey 沙箱计时器清理错配：等待的 timeout、interval 在所属页面 window 创建和清理，sleep 使用同一页面 window，完成处理增加 settled 保护，避免清理其他作用域的计时器或重复完成。

刷新后，只有旧 single 实例的不确定项无提交意图、完全无 actual、journal 精确匹配 assignment/task/batch 且为 filling、command 无任何 grant，才转为明确失败。原分配和日志保留，后续由“重试明确失败项”显式清除归属。多页、当前实例及任一证据缺失均不适用；许可过期也不等同从未提交。本轮该路径已将原第 3 条恢复为明确失败并执行产品重试。该条前两次填表尝试均未提交（0.4.6 填表停滞，随后 0.4.7 页面未就绪），第 3 次成功并完成保存后核验。

主控唯一派发，提交意图与 journal 持久化，许可有时限并受账号节流控制。暂停、停止、刷新、超时或后台冻结不清除已有提交证据。历史已创建待核验任务不恢复成可重建任务，未收齐结果的原分配不自动重派；仅确认未提交的明确失败项可限次重试。

0.4.9 在执行页 ACK 或报告通信失败后，只有已有提交意图且当前成功说明精确匹配该任务时才恢复 ID，持久化为未核验结果。已有终态 journal 不被错误覆盖。暂停批次的缺 ID 待核验行也可通过“记录 ID 并核验”录入真实已观察值：限定本发布商合法 `/` ID，先保存 `verified:false`，再沿用原核验流程；不重新提交、不直接标成功、不覆盖不同的已知 ID。该功能的源码实现与真实恢复验收分别记录。

探测期间的 `a[data-action="open-worker"]` 仅展示合法 AdMob HTTPS 地址和执行页标识，探测结束后清除。默认使用 `GM_openInTab`；原会话可手动补开，自动化宿主也可设置 `data-manual-tabs`，由 Playwright 在原 HubVPS context 内 `newPage().goto(link.href)`。它复用原 hello、Web Locks、GM 通知、身份检查与主控调度，不能跳过探测或提交门槛。Playwright 扩展已连接原 Chromium 126，但浏览器连接、多开标签、握手通过与真实多页创建是不同验收项。

## 中断修复与剩余边界

0.5.1 修复前两项并增加本地回归；主控在途刷新另有隔离浏览器验证。尚未做真实暂停、睡眠或在途刷新故障验收；历史五条目标只验收不中断的连续运行。

1. **主控在途刷新（已修复）**：按持久化分配重建报告收集槽；匹配 batch/task/assignment/worker 的终态 journal 可补回迟到结果。保留原归属，不重新派发创建。隔离浏览器已验证提交后、返回 ID 前刷新仍只创建一次并完成保存后核验。
2. **最后许可与点击之间（已修复）**：所有异步身份检查结束后，在原生点击前同步检查批次状态、任务归属及许可有效期。已发出的创建请求继续收集结果，暂停和停止不撤回已发请求。
3. **执行页刷新角色**：`GM_getTab` 缺失、超过等待时间或保存失败时，URL 的 worker 标记已被删除，刷新可能无法恢复 worker 身份并误走主控启动。通常会被主控锁阻止；这不表示执行页自动刷新恢复已通过。

## 环境与数据边界

使用现有 HubVPS 启动器及已登录会话，不复制或重建启动令牌，不改变内核、代理、指纹、UA、IP、时区或系统默认浏览器。本轮通过 Playwright 连接原 HubVPS，使用真实页面及原生可访问性控件完成安装、刷新、重试和继续，并保留截图与状态证据；不依赖 HubStudio 团队扩展或云端 API。
