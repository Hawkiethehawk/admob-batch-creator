# 页面适配与真实验收状态

截至 2026-11-12，开发环境没有可读取的已登录 AdMob 目标应用页面；没有创建任何真实测试广告位。`src/adapter.ts` 是基于标准 HTML/ARIA 关联的中文语义适配器，已通过模拟 DOM 测试。它尚未对应某个真实 AdMob 后台版本完成选择器校准，不能将模拟测试当作线上验收。

## 当前识别范围

- 仅从可见、明确关联的“发布商 ID”“应用 ID”“应用名称”字段读取当前上下文。支持 `dt/dd`、单值 `th/td`、只读关联控件和明确 `aria-label`。不扫描整页 ID，不读取页面内部状态，不猜 URL 参数，不使用历史账号缓存。
- 列表需有语义表格和明确的“广告单元名称”列，并有可核对的“共 N 个广告单元”总数。分页使用可见的“第一页”“下一页”控件；每次查重从可观察的第一页重新读取。列表上级主区域存在搜索文本、选中的非“全部”筛选或可清除筛选时，返回“不完整”，不会把局部列表当作不存在。无法证明完整时返回“待核验”。列表中的同名条目缺少格式、模式、底价或币种证据时，不会按“已存在且一致”跳过。
- 创建页需有明确格式卡片、关联名称输入、手动底价单选项、全局底价区域及关联金额输入。未知结构、重复候选、国家/地区或中介组区域均阻止提交。
- 仅底价输入本身的关联标签/说明或紧邻的单输入容器明确显示 `USD`、`US$`、美元时允许填值；其他币种和单独 `$` 阻止提交。页面报告币种、付款币种不作为证据。读取真实 `min`/`max`/`step`/`maxlength` 约束。
- 保存后要求明确的广告单元 ID 和只读配置字段；仅看到成功提示或实现说明不能认定全部成功。若跟随真实详情链接，必须再次读取相同广告单元 ID，不能将一个 ID 与另一个单元的底价配置合并。已取得 ID 时始终保留，并报告“已创建但配置待核验”。

## 待真实页面校准

1. 当前账号发布商 ID 与目标应用 App ID 在实际后台的关联结构。它们可能不同时显示；此时当前实现会停止，需要根据只读页面证据补充导航与识别。
2. 实际广告单元列表结构、筛选状态、分页总数及已存在单元的配置详情导航。
3. 插页式、开屏卡片与创建表单的真实 HTML/ARIA；Google 自定义组件可能需要在语义关联证据明确后补充组件适配。
4. 手动全局底价和实际 USD 币种提示的位置、页面范围与精度校验。
5. 创建结果的广告单元 ID 和保存后配置页面，及 SPA 与完整页面跳转的恢复行为。

先使用面板导出脱敏诊断定位控件关联，再在用户确认的真实清单上由用户点击“开始创建”。诊断不包含页面 HTML、输入值、Cookie、Token、邮箱、应用名称或原始账号 ID。它可辅助结构定位，但不能单独证明账号或配置正确。

缺少以上校准时，首版可能因无法识别而阻止预检/创建。这是实际交付限制，不能宣称已达到真实 AdMob 批量创建验收。Chrome、Edge 中的真实 Tampermonkey 安装、真实后台流程及 HubVPS 实机兼容性需分别验收。
