## 清单与整批设置

在原已登录中文 AdMob 目标应用的广告单元列表打开面板，核对发布商、应用和 App ID。App ID 使用 `~`，广告位 ID 使用 `/`，不能互换。

整批格式可选择插页式/插屏、开屏、信息流（原生广告）；每种格式均提供人工指定底价、由 Google 优化、已停用，默认人工。人工模式使用全局 USD/千次展示，其他两种模式只需名称。脚本严格核验所选模式，不在出错时自行切换模式。不设置国家/地区专属底价或中介组瀑布流 eCPM。

每行只填名称和该行底价：

```csv
广告位名称,底价USD
US_NEW_INT_60,60
US_NEW_INT_40,40
```

粘贴 Excel、TSV/CSV 或导入文件后立即成为可编辑清单，无需另点解析，也没有解析档案。人工模式需要名称、底价两列；Google 优化和已停用模式支持每行一个名称。名称含逗号时使用标准 CSV 双引号。原始行号保留。输入 `60` 表示 60 USD/千次展示，仅接受明确的非负十进制金额，不接受货币符号、千分位、指数或逗号小数点。名称不自动截断，最多 80 字符；金额上限、零值和精度以真实字段规则为准。

填写“名称前缀”并点击“批量应用前缀”。重复点击不会叠加；修改前缀后再应用可替换，清空后应用可恢复原名称。手动编辑过的名称会作为该行新的基础名称。前缀过长等错误直接显示在行内。

面板并发范围为 1～5、默认 5，原会话中五任务真实并行已通过。自动开页未出现时，可用探测期间的“打开执行页”链接补开原会话执行页。每次新会话仍须通过能力检查。

## 新批次开始

1. 点击“重新识别”，核对当前发布商及应用。无明确页面身份或身份不匹配时停止。
2. 选择格式、底价模式、执行方式和并发数；执行方式界面暂保留原有单页/多页选项。可选的“检测跨页能力”用于只读连接诊断。
3. 粘贴/导入清单，按需应用前缀并修正行内错误。核对账号、格式、模式和名称；人工模式还需核对每行金额。
4. 勾选整批确认，点击“开始创建”一次。脚本自动核对账号、主控锁和输入，并预热执行页、检查跨页锁和通知。修改清单或设置会清除确认。自动开页未出现时，可在探测期间点击“打开执行页”，在同一浏览器配置中补开。
5. 通过历史样本重新核验时，主控可直接按所选并发派发新清单；否则先核验本批首条，再扩展并发。每条新行仍须取得自己的新 ID 并独立保存后核验。保持主控和执行页打开；任务并行执行，原生提交仍至少间隔 2.5 秒。

自动检查不会查询同名；若有同发布商、应用、格式和底价模式的历史成功样本，会按其 ID 只读重新核验后复用首条门控。样本已删除、不可用或不一致时，重新检查身份并改用本批首条核验，不依赖旧广告单元存在。

执行准备时才打开创建表单，选择精确格式卡、填写名称、展开高级设置并选择所需底价模式；人工模式再等待金额组件、填写 USD 金额并读回。插页式激励广告不会被当作插页式。

0.4.8 已用 1000 行清单回归预检及派发消息，降低大清单反复存储和跨页传输开销；这不表示一次并发创建 1000 条。原始行号、逐行日志、提交意图和结果仍保留，实际并发上限为面板选择的 1～5。

底价模式和人工金额已由批次确定，无需单独确认。每条提交前自动核对身份、格式、名称和模式，人工模式还核对金额与 USD；页面只显示 `$` 时按批次 USD 解析，明确显示非 USD 或读回配置冲突时停止并报告。主控先持久化并回读提交意图，执行页再取得短时提交许可，最后只点击一次创建。

AdMob 的原生底价组件可能把输入 `1000` 自动显示为 `1,000.00`。0.4.14 仅在该已知组件内接受规范千分位显示，并继续精确比对完整金额；错误分组、金额变化和普通控件仍会阻断。用户导入、手填金额继续使用 `1000` 或 `1000.00`。

自动化多开时，Playwright 读取面板当前“打开执行页”的合法链接，并在原 HubVPS 的同一 context 中新建标签。每页继续由同一用户脚本完成跨页握手、领取任务和提交保护；Playwright 负责开页和页面控制，不建立另一套任务调度。此次 5/5 使用该方式（`data-manual-tabs`），并轮流 `bringToFront` 避免后台节流；默认 `GM_openInTab` 自动开页只做源码审查，所有页长期后台、最小化或睡眠未验收。连接维护方法见 [Playwright浏览器控制.md](../Playwright浏览器控制.md)。真实多页创建与五并发状态见 [验证记录](VALIDATION.md)。

0.4.9 将报告通知直接交给主控收集并返回 ACK，保留轮询作为恢复途径。预热页会在真实派发前就绪，减少运行时新开页探测拖住已有结果收集的情况；最终并发验收仍须查看真实结果。

## 中断批次的恢复与核验

以下步骤用于被中断或尚待核验的批次；首批 100～500 已完成，无需继续执行：

1. 保持原批次暂停，核对原发布商和应用。底价沿用批次设置，已有 ID、意图和执行归属保留。新版不再提供独立预检按钮，继续时会重新检查身份与锁。
2. 已有提交意图、尚无已知 ID，但真实成功说明显示了对应任务 ID 时，在该行“成功说明中的广告位 ID”输入框录入完整值，点击“记录 ID 并核验”。仅接受本发布商 ID；先保存为未核验，再读取保存详情，不重新提交。不同已知 ID 不能覆盖。
3. 已有 ID 时点击“核验结果不确定项”，按该 ID 读取同一保存后详情，核对 ID、名称、格式、该行人工底价和 USD。脚本最多 20 秒等待精确 ID 行，旧搜索行或旧“共 0 行”不能直接当作缺失。返回不同 ID 时保留原记录，不能标记成功。
4. 不再要求恢复标签页的 US$ 会话证据，也没有独立请求币种控件。人工模式按已确定的 USD 使用，不为补证额外访问创建表单。
5. 保存详情的 `$100.00` 直接按该批 USD 解析，例如请求为 100 时自动比对为一致。明确非 USD、金额或人工模式冲突时保留待核验并报告；不会修改或重建已有广告位。
6. 存在待核验结果时，“继续”禁用并显示原因；直接调用恢复逻辑也不能绕过。核验通过后仍保持暂停，继续当前批次才会执行尚未提交的请求。

不要重新点“开始创建”或新建同一清单来恢复任务。自动化操作通过 Playwright 连接原浏览器，按真实页面按钮文字或稳定的 `data-action` 定位，不使用控件数组固定索引：五行恢复批次中的 `[22]` 实际是第 5 行底价输入，并非“继续”。不要修改 disabled 属性绕过检查。

已有真实 ID 却未出现在主控当前行时，保留原执行页；主控刷新后会恢复原任务的报告收集，并读取匹配的终态 journal。缺少本次 ID 时保持待核验，可录入成功说明中的真实 ID；同名旧记录不会被当作本次结果，也不能据此重新提交。

## 暂停、继续、降级和停止

“暂停”停止后续派发，保留原任务和结果证据。“继续”重新核对原身份、锁和确认状态；存在待核验项或持久化停止意图时拒绝恢复。实际点击创建前会同步复查批次状态、任务归属和许可；已经发出的创建请求继续收集结果。

多页运行中或暂停后可“降级为单页”。旧执行页保留并继续收集结果，后续可派发任务改在当前页处理；已提交或结果不确定的任务不会因此重新分配创建。

“停止”不再新建，不删除广告位，也不立即关闭仍需收集结果的插件执行页。停止意图刷新后仍有效。仅对确认无提交意图、无已知 ID 的明确失败项开放安全重试，最多三次；重试操作准备任务后仍等待“继续”。

刷新主控后，未确认的草稿须检查清单后通过“开始创建”确认，点击后自动检查执行条件；已开始批次恢复为暂停。提交意图不会重置为待执行。0.4.7 对旧单页实例提供严格恢复：刷新结束旧实例后，只有不确定项无提交意图、无实际结果、匹配 assignment/task/batch 的 journal 仍为 filling，且没有任何提交许可，才转为“明确失败”，由重试操作清除旧归属。多页、当前实例、日志不匹配或证据缺失均不适用。执行日志新增“表单已读回，等待提交许可”，便于区分填表与提交阶段。

后台冻结、通信超时或当前列表未出现记录本身都不能证明创建失败；保留原 ID 和分配，先核验，禁止盲目重建。只管理插件创建的执行页，不关闭用户原有标签页。

主控在途刷新恢复已通过隔离浏览器验证。`GM_getTab` 不可靠时，执行页刷新仍可能丢失角色；完整真实环境中断流程尚未验收，详见 [适配限制](adapter-limitations.md)。

创建成功后的原执行页会从真实成功说明区取得新 ID，先持久化，再按 ID 读取保存详情。0.5.2 起，“核验结果不确定项”不再自动采纳主控当前页面的成功说明：同名说明可能来自旧创建，无法证明对应本次分配。已有意图但缺少 ID 时，保留原执行页等待报告，或通过“记录 ID 并核验”录入本次实际观察到的 ID。未完成保存后核验的行保持待核验，绝不再次点击创建。

主控和执行页先后刷新时，若旧分配的填表记录完整匹配且没有提交意图、结果或任何许可，执行页会回报明确失败，再由“重试明确失败项”恢复。证据不足或存在提交迹象时仍须核验；不会自动重建。账号提交锁覆盖最后点击，各页延迟不会让后续页并抢提交；结果核验仍可并行。

0.4.9 的执行页在 ACK 或报告通信失败后，也会尝试从当前精确匹配的成功说明恢复 ID，并保留为“已创建但配置待核验”。拿到 ID 后仍须完成保存后核验，不能因通信失败重提，也不能把补录或成功说明本身直接计作成功。

## 结果与导出

“任务批次”可选当前任务或当前发布商与应用的历史批次。查看历史时，创建/继续/重试等操作禁用；复制与三种导出作用于选中的历史批次，不替换当前正在运行的任务。记录保存在当前浏览器配置中，不跨浏览器同步。

每批显示开始、结束、总耗时；新批次从点击开始起计时，包含自动检查、等待与暂停，重试沿用原开始时间。旧记录有 `confirmedAt` 时显示该已记录时间，缺少结束记录时总耗时为未知，不用最后一行时间推算。CSV 追加批次 ID、开始、结束和总耗时列。

成功要求真实广告位 ID 和保存后的身份、名称、格式、所选底价模式一致；人工模式还要求金额与 USD 一致。明确的币种或配置冲突仍须报告。点击、提示条或跳转均不能单独证明成功。

- **成功**：完整保存后核验一致。
- **已创建但配置待核验**：已有 ID，配置证据不足；不计成功，不可重建。
- **结果不确定**：可能已提交或已有提交意图；只允许先核验。
- **明确失败**：能够确认尚未提交的错误；符合条件才可重试。
- **已存在/冲突**：保留历史状态兼容，当前新请求不因同名而自动跳过。
- **已停止**：停止时尚未派发的任务；不表示已有提交可重新创建。

“导出全部/成功/异常”生成带 UTF-8 BOM 的 CSV，包含原行、身份、请求/实际配置、真实 ID、状态、原因和时间，并处理 CSV 转义及 Excel 公式防护。“复制名称 + ID”可能包含配置待核验项，最终以完整 CSV 状态为准。

“导出脱敏诊断”只导出能力、状态计数及白名单控件结构，不导出凭据、页面 HTML、输入值、账号 ID、原始日志或 URL 查询。执行日志显示中文步骤、累计耗时和本行上一步间隔；时间包含暂停或后台冻结，不等同于 AdMob 服务端处理时间。
