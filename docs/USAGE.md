## 清单与整批设置

在原已登录中文 AdMob 目标应用的广告单元列表打开面板，核对发布商、应用和 App ID。App ID 使用 `~`，广告位 ID 使用 `/`，不能互换。

整批支持横幅、插页式/插屏、激励广告、插页式激励广告、信息流（原生高级广告）、开屏六种格式。未启用合作平台出价时，可选人工指定底价、由 Google 优化、已停用，默认人工；人工模式使用全局 USD/千次展示，其他两种模式只需名称。不设置国家/地区专属底价或中介组瀑布流 eCPM。

未启用合作平台出价时，各格式保留以下已读取的平台默认值，并在提交前检查：

| 格式 | 媒体类型 | 频次上限 | 奖励 |
| --- | --- | --- | --- |
| 横幅 | 文字、图片和富媒体 + 视频 | 不适用 | 不适用 |
| 插页式/插屏 | 文字、图片和富媒体 + 视频 | 已停用 | 不适用 |
| 开屏 | 文字、图片和富媒体 + 视频 | 已停用 | 不适用 |
| 信息流（原生高级广告） | 图片 + 视频 | 不适用 | 不适用 |
| 激励广告 | 视频 + 广告连播 + 互动式 | 已停用 | 1 Reward |
| 插页式激励广告 | 视频 + 互动式 | 已停用 | 1 Reward |

两种激励格式使用平台默认奖励数量 `1`、奖品名称 `Reward`，不自动修改奖励或配置服务器端验证地址。奖励字段缺失、无效或发生变化时阻止提交。新增格式的无提交页面检查不等于真实创建验收。

通过编辑行直接填写任务，创建区没有粘贴/导入入口或文件选择器。在最后一条编辑行下方点击“增加一行”，填写名称；未开启合作平台出价的人工模式还需填写该行底价，例如：

| 广告位名称 | 底价 USD/千次 |
| --- | ---: |
| `US_NEW_INT_60` | 60 |
| `US_NEW_INT_40` | 40 |

Google 优化、已停用模式及合作平台出价只需名称。行内错误需先修正，未完成行可删除。输入 `60` 表示 60 USD/千次展示，仅接受明确的非负十进制金额，不接受货币符号、千分位、指数或逗号小数点。名称不自动截断，最多 80 字符；金额上限、零值和精度以真实字段规则为准。已有历史记录和 CSV 导出继续保留。

“批量应用前缀”仅在人工底价且未勾选合作平台出价时可用。开启后填写前缀，名称立即按“前缀 + 规范化十进制底价”生成并变为只读；修改前缀或底价时同步更新。例如前缀 `admob_int_`、金额 `60.00` 生成 `admob_int_60`，金额 `0.50` 生成 `admob_int_0.5`。前缀为空、名称过长或本清单生成重名会显示行内错误并阻止开始；`60` 与 `60.00` 会生成同一名称。关闭开关恢复原手填名称；启用合作平台出价会关闭该开关。手填模式仍允许 AdMob 支持的重名请求。

“合作平台出价”默认不勾选；插页式激励广告不支持，切换到该格式会取消并禁用该选项，其余五种格式可选。勾选后底价模式禁用、金额不参与创建，按底价生成名称也不可用；预览中的底价、媒体类型和频次上限显示“不适用”。插件只设置并核对实际合作平台出价复选框，不再查找底价选项、填写金额或要求保存后的底价证据。保存后须明确读回合作平台出价启用，且 ID、身份、名称、格式一致才算成功；缺失或冲突时保留 ID 待核验。未勾选时仍严格核验所选底价模式。

可选两种执行方式。

| 执行方式 | 开页和创建顺序 |
| --- | --- |
| **并发（默认）** | 按待执行条数一次打开 `/adunits/create` 页面，按清单顺序逐页在前台创建、读取 ID 并核验。当前任务页关闭后才进入下一页。 |
| 串行（当前页逐条执行） | 使用当前页，每条创建和核验完成后处理下一条。 |

并发模式使用原 AdMob 会话。主控收到当前页的前台确认、核对应用身份后就在已打开的格式选择页开始任务。全部处理后，结果留在主控页。遇到结果不确定时，插件保留涉及提交的页面并暂停。两种方式均使用账号级至少 2.5 秒的提交间隔。

## 新批次开始

1. 点击“重新识别”，核对当前发布商及应用。无明确页面身份或身份不匹配时停止。
2. 选择广告格式、合作平台出价、适用的底价模式和执行方式。默认使用并发，可切换为当前页串行。
3. 通过“增加一行”填写任务，按需开启“批量应用前缀”并修正行内错误。核对名称，未开启合作平台出价的人工模式还需核对每行金额。
4. 点击“开始创建”，打开“创建预览”。身份区显示应用名称、AdMob App ID 和发布商 ID。逐行核对名称、精确格式、对应媒体类型与频次设置、适用的底价及合作平台出价；激励格式还显示 `1 Reward`。合作平台出价开启时，底价、媒体类型及频次为“不适用”。点击“取消”返回编辑，此时尚未启动批次。
5. 点击“确认创建”。并发模式一次打开本批的创建页，逐页切换、核对身份、创建、核验并关闭。串行模式从当前页开始。开页失败时，插件报告原因并保留草稿。
6. 完成后，在“历史结果”中查看保存后配置和每行的新广告单元 ID。

执行准备时才打开创建表单、选择精确格式卡并填写名称。未启用合作平台出价时展开高级设置，选择底价模式；人工模式填写 USD 金额并读回，其他模式不填金额。启用合作平台出价时不进入底价流程。插页式、激励和插页式激励分别识别，奖励及媒体默认值按对应格式核对。

适用的底价模式和人工金额由批次确定，随整批预览检查，无需独立确认。每条提交前自动核对身份、格式、名称和合作平台出价；未启用合作平台出价时再核对底价模式，人工模式还核对金额与 USD。人工金额页面只显示 `$` 时按批次 USD 解析，明确非 USD 或读回冲突时停止并报告。主控先持久化并回读提交意图，执行页再取得短时提交许可，最后只点击一次创建。

AdMob 的原生底价组件可能把输入 `1000` 自动显示为 `1,000.00`。0.4.14 起仅在该已知组件内接受规范千分位显示，并继续精确比对完整金额；错误分组、金额变化和普通控件仍会阻断。编辑行中的金额继续使用 `1000` 或 `1000.00`。

## 中断批次的恢复与核验

以下步骤用于尚未停止、被中断或待核验的活动批次；首批 100～500 已完成，无需继续执行。已经显示“已停止”的批次使用下文历史核验流程，不再继续或重试创建：

1. 保持原批次暂停，核对原发布商和应用。底价沿用批次设置，已有 ID、意图和执行归属保留。新版不再提供独立预检按钮，继续时会重新检查身份与锁。
2. 已有提交意图、尚无已知 ID，但真实成功说明显示了对应任务 ID 时，在该行“成功说明中的广告位 ID”输入框录入完整值，点击“记录 ID 并核验”。仅接受本发布商 ID；先保存为未核验，再读取保存详情，不重新提交。不同已知 ID 不能覆盖。
3. 已有 ID 时点击“核验结果不确定项”，按该 ID 读取同一保存后详情，核对 ID、名称、格式及合作平台状态；未启用合作平台出价时还核对底价模式，人工模式核对金额和 USD。脚本最多 20 秒等待精确 ID 行，旧搜索行或旧“共 0 行”不能直接当作缺失。返回不同 ID 时保留原记录，不能标记成功。
4. 不再要求恢复标签页的 US$ 会话证据，也没有独立请求币种控件。人工模式按已确定的 USD 使用，不为补证额外访问创建表单。
5. 保存详情的 `$100.00` 直接按该批 USD 解析，例如请求为 100 时自动比对为一致。明确非 USD、金额或人工模式冲突时保留待核验并报告；不会修改或重建已有广告位。
6. 存在待核验结果时，“继续”禁用并显示原因；直接调用恢复逻辑也不能绕过。核验通过后仍保持暂停，继续当前批次才会执行尚未提交的请求。

恢复旧任务时不要通过“开始创建”重新提交同一清单。停止归档后可填写独立的新请求，原批已有提交意图或已知 ID 的行仍只能核验。自动化操作通过 Playwright 连接原浏览器，按真实页面按钮文字或稳定的 `data-action` 定位，不使用控件数组固定索引：五行恢复批次中的 `[22]` 实际是第 5 行底价输入，并非“继续”。不要修改 disabled 属性绕过检查。

已有真实 ID 却未出现在主控当前行时，保留原执行页；主控刷新后会恢复原任务的报告收集，并读取匹配的终态 journal。缺少本次 ID 时保持待核验，可录入成功说明中的真实 ID；同名旧记录不会被当作本次结果，也不能据此重新提交。

## 暂停、继续、降级和停止

“暂停”停止后续派发，保留原任务和结果证据。“继续”重新核对原身份、锁和确认状态；存在待核验项或持久化停止意图时拒绝恢复。实际点击创建前会同步复查批次状态、任务归属和许可；已经发出的创建请求继续收集结果。

多页运行中或暂停后可“降级为单页”。旧执行页保留并继续收集结果，后续可派发任务改在当前页处理；已提交或结果不确定的任务不会因此重新分配创建。

“停止”持久化停止意图并撤销原提交许可，批次归档显示“已停止”。未派发且没有分配的行记为停止；存在提交或未决结果的行保留 ID、原分配及提交证据。停止不删除广告位，也不关闭仍需收集未知提交结果的原执行页；迟到结果写回原历史，旧页不占新批次执行名额。刷新后停止意图仍有效，已停止批次不再提供继续、重试或降级创建。

停止后原编辑清单会清空一次，可填写独立新请求并点击“开始创建”查看预览。刷新不会把停止清单重新填回编辑器；后续历史或核验更新也不会覆盖独立新草稿。新预览仍需“确认创建”才执行，取消不提交。手填名称允许重名的规则保留，但已有提交意图或已知 ID 的旧行不能借新批次重新创建。

仅尚未停止的活动批次，才对确认无提交意图、无已知 ID 的明确失败项开放安全重试，最多三次；重试操作准备任务后仍等待“继续”。

刷新主控后，未确认的草稿须检查清单，点击“开始创建”打开预览，再“确认创建”启动执行条件检查；已开始批次恢复为暂停。提交意图不会重置为待执行。0.4.7 对旧单页实例提供严格恢复：刷新结束旧实例后，只有不确定项无提交意图、无实际结果、匹配 assignment/task/batch 的 journal 仍为 filling，且没有任何提交许可，才转为“明确失败”，由重试操作清除旧归属。多页、当前实例、日志不匹配或证据缺失均不适用。执行日志新增“表单已读回，等待提交许可”，便于区分填表与提交阶段。

后台冻结、通信超时或当前列表未出现记录本身都不能证明创建失败；保留原 ID 和分配，先核验，禁止盲目重建。只管理插件创建的执行页，不关闭用户原有标签页。

主控在途刷新恢复已通过隔离浏览器验证。`GM_getTab` 不可靠时，执行页刷新仍可能丢失角色；完整真实环境中断流程尚未验收，详见 [适配限制](adapter-limitations.md)。

创建成功后的原执行页会从真实成功说明区取得新 ID，先持久化，再按 ID 读取保存详情。0.5.2 起，“核验结果不确定项”不再自动采纳主控当前页面的成功说明：同名说明可能来自旧创建，无法证明对应本次分配。已有意图但缺少 ID 时，保留原执行页等待报告，或通过“记录 ID 并核验”录入本次实际观察到的 ID。未完成保存后核验的行保持待核验，绝不再次点击创建。

主控和执行页先后刷新时，若旧分配的填表记录完整匹配且没有提交意图、结果或任何许可，执行页会回报明确失败，再由“重试明确失败项”恢复。证据不足或存在提交迹象时仍须核验；不会自动重建。账号提交锁覆盖最后点击，各页延迟不会让后续页并抢提交；结果核验仍可并行。

0.4.9 的执行页在 ACK 或报告通信失败后，也会尝试从当前精确匹配的成功说明恢复 ID，并保留为“已创建但配置待核验”。拿到 ID 后仍须完成保存后核验，不能因通信失败重提，也不能把补录或成功说明本身直接计作成功。

## 结果与导出

“任务批次”可选当前任务或当前发布商与应用的历史批次。查看历史时，创建/继续/重试等操作禁用；复制与三种导出作用于选中的历史批次，不替换当前正在运行的任务。切回当前任务即可编辑新清单。记录保存在当前浏览器配置中，不跨浏览器同步。

对于“已停止”的历史批次，可点击“核验结果不确定项”，按原已知 ID 读取保存配置。已有提交意图却没有 ID 时，只能录入真实成功说明中已观察到的本次完整 ID，再点击“记录 ID 并核验”；先保留为待核验，不能直接标成功或覆盖不同已知 ID。两项操作只更新所选历史，不恢复创建、不替换另一当前批次。新批次运行或停止中暂不可核验/补录历史，需先暂停并收齐当前结果。原 ID 缺失或证据不足时继续保留未决状态。

每批显示开始、结束、总耗时；新批次从预览“确认创建”实际启动起计时，包含自动检查、等待与暂停，重试沿用原开始时间。只打开预览或取消不会开始计时。旧记录有 `confirmedAt` 时显示该已记录时间，缺少结束记录时总耗时为未知，不用最后一行时间推算。CSV 追加批次 ID、开始、结束和总耗时列，已有历史导出及记录保留。

成功要求真实广告位 ID 和保存后的身份、名称、格式一致。未启用合作平台出价时还需底价模式一致，人工模式要求金额与 USD 一致；启用时不要求底价，须取得明确一致的保存后合作平台出价启用状态。证据缺失保留 ID 待核验，明确冲突须报告。点击、提示条或跳转均不能单独证明成功。

- **成功**：完整保存后核验一致。
- **已创建但配置待核验**：已有 ID，配置证据不足；不计成功，不可重建。
- **结果不确定**：可能已提交或已有提交意图；只允许先核验。
- **明确失败**：能够确认尚未提交的错误；符合条件才可重试。
- **已存在/冲突**：保留历史状态兼容，当前新请求不因同名而自动跳过。
- **已停止**：行状态表示停止时尚未派发的任务；批次标题表示已归档且不再创建，其行仍可能含成功或未决结果，不表示已有提交可重新创建。

“导出全部/成功/异常”生成带 UTF-8 BOM 的 CSV，包含原行、身份、请求/实际配置、真实 ID、状态、原因和时间，并处理 CSV 转义及 Excel 公式防护。“复制名称 + ID”可能包含配置待核验项，最终以完整 CSV 状态为准。

“导出脱敏诊断”只导出能力、状态计数及白名单控件结构，不导出凭据、页面 HTML、输入值、账号 ID、原始日志或 URL 查询。执行日志显示中文步骤、累计耗时和本行上一步间隔；时间包含暂停或后台冻结，不等同于 AdMob 服务端处理时间。
