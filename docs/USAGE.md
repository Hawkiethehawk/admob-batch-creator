# 使用 AdMob Batch Creator

先按 [安装说明](INSTALL.md)安装。当前真实 AdMob 中文后台、Tampermonkey 安装与 HubVPS 兼容性仍待验收；脚本遇到当前语义适配器不认识的页面会停止。详见 [页面适配限制](adapter-limitations.md)。开发和自动化测试不会在真实 AdMob 中新增测试广告位。

## 准备清单

进入已经登录的中文 AdMob 目标应用，打开广告单元页面。面板可收起，展开后先检查当前发布商 `pub-…`、应用名称和 App ID。App ID 中间是 `~`，创建后的广告位 ID 中间是 `/`，两者不能互换。

在“整批设置”选择“插页式 / 插屏”或“开屏”。首版整批使用“手动设定底价”和 USD，不会在手动设置失败时改成 Google 优化，也不配置中介组瀑布流或国家/地区专属底价。

每行只填名称与该行底价。例如：

```csv
广告位名称,底价USD
US_NEW_INT_60,60
US_NEW_INT_40,40
US_NEW_INT_20,20
US_OLD_INT_15,15
```

可以从 Excel 复制两列，也可以粘贴 TSV/CSV 或导入 CSV 文件。粘贴后点击“解析到清单”，再在表格内编辑、增加或删除行。原始行号会保留，便于对照输入来源。名称含逗号时请使用标准 CSV 双引号，例如 `"US,INT",60`。

输入 `60` 表示 60 美元/千次展示。仅使用无歧义的非负十进制金额，例如 `0`、`15`、`60.25`；不接受货币符号、千分位、指数或逗号小数点。零值、上限和小数精度能否使用，仍以真实 AdMob 字段规则为准。名称不自动截断或追加后缀，空名称、重复名称、缺失底价及解析错误需要逐行修正。

## 预检与开始

1. 点击“重新识别”，核对发布商与目标应用。没有选中应用、身份无法确认或账号不匹配时先解决识别错误。
2. 选择并发数 1～3，默认 2；也可选择单页模式。多页模式需要“检测跨页能力”通过。并发数是插件配置，不代表 AdMob 官方并发额度。
3. 点击“预检（不提交）”。脚本固定本批发布商与应用，读取目标应用已有广告位并检查同名结果。多页模式还会检查当前会话的执行页与通信能力。预检不会点击“创建广告单元”。
4. 查看逐行结果及检查清单。同名同格式同手动 USD 底价且配置已完整核验的条目记为“已存在”；同名配置不同记为“冲突”；多重同名、分页/筛选读取不完整或配置无法确认的条目进入待核验，不会创建。
5. 勾选整批确认，再点击“开始创建”。这一次点击确认整个清单，不逐条弹窗。修改清单、格式、并发或执行方式后必须重新预检。

执行中冻结当前批次设置。主控先派发一条；只有首条实际创建后配置核验一致，才逐步增加到选定并发。跳过已有匹配条目不能证明创建流程可用，因此不会解除首条限制。执行标签页池会重复使用。保持主控和插件执行页打开，不要手动修改执行页表单。

每条提交前都会再次核对发布商、应用、格式、名称、手动全局底价、金额和真实币种，并保存提交意图及任务归属。底价控件必须明确关联 USD、US$ 或美元证据；只看到含义不明的 `$`、其他币种或关联结构不明时阻止提交，不自动换汇。

## 暂停、降级与停止

“暂停”停止派发新任务，尚未提交的任务在安全步骤停下；已经提交的任务继续收集真实 ID 和保存后配置。“继续”会先重新核对原发布商及原应用，再恢复尚可派发的任务。恢复登录后也需回到该批原账号与原应用。

多页模式运行中或暂停后可以点击“降级为单页”。旧执行页仍保留并继续跟踪其结果；后续可执行任务改由当前页处理。降级不会把正在提交或结果不确定的任务交给当前页重新创建。

“停止”不再发起创建，保留已有结果，不删除任何广告位，也不立即关闭尚未收齐结果的执行页。停止后仍保留“核验结果不确定项”入口；若原执行页还在处理或当前页尚未安全空闲，运行时会阻止冲突核验并说明原因。当前批次结束后才能预检新批次，不能覆盖未完成的记录。

停止请求会持久化，刷新后也不会直接恢复创建。预检时读取不完整但从未分配、从未提交的行，会保留原状态、原因和已有 ID；这些记录不会阻止一个未提交的批次结束。已经提交或取得本批创建 ID 的不确定结果，停止后仍需核验，不能覆盖成新批次。

停止后若明确选择“重试明确失败项”，只有未提交、没有已创建 ID、未耗尽次数且旧执行页结果已收齐的失败项可以重新准备；这一步才会清除停止标记，随后仍需点击“继续”。没有可安全重试项时，停止标记保持不变。

同一发布商只能有一个活动主控。需要在另一标签页恢复时，先结束或关闭旧主控；不要通过复制标签页来绕过互斥限制。仅当前浏览器配置内共享状态，不会跨浏览器、跨 VPS 同步执行中的批次。

## 结果与异常恢复

成功要求取得真实广告位 ID，并从保存后的页面核对应用、名称、格式、手动底价、金额和 USD。按钮点击、提示条或页面跳转都不能单独作为成功证据。

主要结果状态：

- “成功”：真实 ID 和保存后的请求配置已核验一致。
- “已存在”：确认已有同名、同格式、同配置条目，保留已有 ID，跳过创建。
- “明确失败”：能够确认未提交的错误；“重试明确失败项”只准备安全项，最多三次，点击“继续”后按退避规则执行。
- “结果不确定”：有提交意图或可能已提交，但尚未获得足够结果证据。只能先核验，不能盲目重建。
- “已创建但配置待核验”：已取得广告位 ID，底价或其他配置未完整核验。保留 ID，不能计入完全成功，也不能用重新创建解决。
- “冲突”：同名条目的格式、模式、金额或币种不同，不修改已有广告位，不自动改名。
- “已停止”：停止时未派发的条目；已有提交不因停止变成可重建项。

刷新主控或执行页后，从本机持久化记录恢复。未开始的预检批次仍须通过“开始创建”确认；已经开始的历史批次恢复后暂停，等待用户点击“继续”。历史提交意图不会被重置成待执行。

对于“结果不确定”或“已创建但配置待核验”，点击“核验结果不确定项”。查询暂时没有出现记录，只说明当前没有查到，不能证明此前创建失败。已取得 ID 时还要确认核验结果对应同一 ID；同名但 ID 不同的条目不会覆盖原记录。

后台标签页延迟、冻结或心跳/通信超时不意味着任务失败，脚本会保留原分配，不立即重派。先保留原执行页，恢复登录或页面访问后核验。如果真实后台缺少当前适配器要求的身份、列表总数或保存后底价字段，需先完成页面适配，不能强行跳过检查。

若旧执行页恢复后明确回报尚未提交，或主控有拒绝提交许可且从未授予许可的记录，可以收集为“明确失败”；这与仅凭心跳超时断言失败不同，仍需用户明确选择重试。

## 导出与诊断

“导出全部”“导出成功”“导出异常”生成带 UTF-8 BOM 的 CSV，包含原始行号、发布商、应用、名称、请求及实际底价、真实广告位 ID、状态、原因和完成时间。中文、逗号和双引号会按 CSV 转义，可能被 Excel 解释为公式的文本会作文本防护。成功导出包括“成功”和已完整核验的“已存在”，配置待核验项属于异常。

“复制‘名称 + ID’”复制已有真实广告位 ID 的条目；该操作也可能包含配置待核验项，因此最终结论以完整结果 CSV 的状态为准。

“导出脱敏诊断”生成 JSON，包含脚本能力、环境 User-Agent、状态数量、执行页检测情况及白名单控件结构。它不导出 Cookie、Token、密码、页面 HTML、输入值、账号 ID、应用/广告位名称、原始日志或 URL 路径和查询参数。结果 CSV 是业务记录，包含账号、应用与名称；它与脱敏诊断用途不同。

执行日志显示中文步骤、错误原因、批次累计耗时和本行上一步间隔。时间按日志时间戳计算，包含暂停或后台冻结期间经过的时间；它是实际经过时间，不是 AdMob 服务端处理时间。日志显示前会隐藏常见凭证形态。

若面板未显示，按安装说明检查扩展与脚本权限。若面板显示“识别失败”“未知页面”或“币种不明”，保留具体步骤和原因并导出诊断。当前语义适配未完成真实后台校准时，诊断只能辅助定位，不能证明线上流程可用。
