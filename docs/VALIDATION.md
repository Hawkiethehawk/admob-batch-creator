## 历史测试与剩余验收

以下三项是源码审查确认的条件性边界，没有作为现场通过项目，也没有在本轮冻结源码时扩范围修改：

1. **主控刷新后的迟到结果收集**：`load` 先调用 `recoverTask` 将 filling/submitting/verifying 转为 failed/uncertain/created-unverified，再仅按原执行态重建 slot，导致在途 slot 不会恢复，旧 worker 晚到的报告或 ID 不能自动收回。原提交意图、归属和已知 ID 保留，不能据此判定未创建或重建。
2. **取消及睡眠恢复的点击边界**：worker checkpoint 先核对许可，再异步核对身份；adapter 提交前又等待身份，真正点击前没有再核对许可/归属。若许可核对后发生身份等待、冻结恢复、暂停/停止、换主或许可到期，仍存在继续到点击的路径。这不证明正常不中断测试失败，但不能宣称暂停、睡眠或过期许可在最后点击处完整阻断。
3. **执行页刷新角色恢复**：`GM_getTab` 缺失或两秒超时返回空状态；保存 worker ID 后删除 URL marker，后续只依赖 tabState。若读取或保存不可靠，普通刷新可能丢失 worker 角色而走主控路径，通常会被主控锁挡住，不能保证自动恢复为原 worker。
